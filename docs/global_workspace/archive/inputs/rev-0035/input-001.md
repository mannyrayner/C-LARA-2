I have been trying it out, and it works, but unfortunately I think we have broken one of our basic principles and allowed this to become too complicated. We need a much simpler model which is immediately comprehensible. Perhaps something like the following:



1. No fine-grained control of one's own contributions to a dictionary: the user can withdraw all of them, moving them to a private-only area, they can view their saved private contributions, or they can restore them. No other operations are supported.
2. The withdraw/restore controls are easy to find in the top-level dictionary page, and the specific control shown is sensitive to the state of the user's content (withdrawn/not withdrawn).
3. If the user's content for this dictionary is not withdrawn, i.e. default state, the "withdraw my content" control allows the user to withdraw everything, with an option to view it first.
4. If the user's content for this dictionary is withdrawn, the "restore my content" control allows the user to restore all their withdrawn content, with an option to view it first.
5. If the user's status for the dictionary is "withdrawn", they can't add new content until they restore the old content, and they can't browse any content.
6. If the user's status for a given dictionary is "withdrawn", this is shown clearly at the platform top level, with the "restore" control next to it.



So the conceptual model for withdrawing your data is that you are leaving the project, saving everything so that you have the option of changing your mind and rejoining. The fine-grained control we have now is potentially useful, but I think most people, particularly in Indigenous communities, will only find it confusing.
