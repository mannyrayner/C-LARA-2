# Community Dictionaries co-owners

## Co-owners

An original owner or active co-owner can share management with other accounts using **People → Invite
an account → Co-owner**. New invitees must sign in and accept the invitation on
**My dictionaries**. For an existing member, use their Role control to select
**Co-owner**. In a dictionary using two-person decisions, the proposal still needs
a different coordinator’s approval. New accounts must first join as ordinary members
before a co-owner role is proposed under that policy. There is no fixed limit on
the number of co-owners.

Active co-owners can change dictionary settings, manage ordinary memberships,
review contributions and use **Download this dictionary and its media** at the
bottom of the dictionary page. The ZIP includes the same entries, contributor
credit and shared media as the original owner’s download. Individual contribution
control and the exclusion of withdrawn material are unchanged.

Any active owner or co-owner can appoint further co-owners. Only the original
owner can remove co-ownership, including making a
co-owner inactive. Co-owners cannot demote the original owner. A withdrawn,
inactive or unaccepted co-owner has no management or download access. Removing
the role blocks future requests, including a previously saved download URL; it
cannot recall an exported ZIP. Two-person membership policy remains in force.

Co-ownership grants no site-administrator status, account credentials, personal API
keys, credits or access to another person’s private AI previews. New paid work
uses the initiating account’s existing billing and consent rules. Google project
billing still requires explicit permission from a site administrator who is an
active owner or co-owner; revocation invalidates that owner’s saved permission.

For installation, see [the one-time preparation and normal release workflow](community-coowners-deployment.md).
