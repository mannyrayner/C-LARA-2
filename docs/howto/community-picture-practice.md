# Describe a picture: private speaking and writing practice

Open **Practise → Describe a picture**. Speak or type a few words in the dictionary's
text language. A description, imagined story or dialogue is welcome. Current
accepted pictures are selected within the chosen category. Another picture avoids
the same image file when another is available.

The first request authorises a practice session. The permission checkbox is then
hidden for up to two hours, until logout or **End practice session**, or until
payment/pricing/dictionary settings change. The session is scoped to the signed-in
user and dictionary. Optional listening still requires pressing its priced button;
replaying an already generated clip is free.

Upload, microphone, feedback-language, voice and proficiency settings are inside
**More options**. These preferences persist independently of contribution settings.
There is no inferred proficiency assessment: the optional self-report guides
explanations, and must never be used to discard unusual vocabulary.

## Speech recognition and feedback

Spoken attempts normally proceed directly from recognition to image-aware review.
The page shows actual stages: recognising words, then checking what was heard and
preparing feedback. There is no invented percentage or simulated streaming.

The review receives input mode and proficiency explicitly. For speech:

- Punctuation, capitalisation and written abbreviation notation are representation,
  not learner mistakes. Swedish `tvn` → `tv:n` can be normalised without criticism.
- The server blocks a proposed normalisation that changes the sequence of letters
  or digits, including diacritics. No language-specific substitution dictionary
  silently turns `bordstuk` into `bordsduk` or `smicke` into `smycke`.
- Suspect recognition, proposed lexical replacements, and spelling corrections
  that change letters are treated as uncertainty before the learner confirms the
  transcript. The app asks one short question and suppresses critical feedback.
- A confirmation/edit permits one additional paid review on the same attempt,
  accounted separately. Recognition is not repeated. Further uncertainty requires
  a revision, rather than an automatic loop.
- Genuine contextual grammar remains available for feedback. This distinction is
  heuristic: the reviewer sees the transcript and image, not the waveform, so it
  can still misclassify an error. Larger real-user samples are needed for tuning.
- Spelling feedback remains available for typed answers. Neither modality produces
  a pronunciation, fluency or proficiency score.

The main result is short, with at most two learning points. **More feedback** opens
full corrections and optional stylistic suggestions. **Words and practice log →
Correct the transcript or edit my words** starts a separate private review from
edited text without buying another transcription. **Try again** offers the same
picture; **Another picture** selects another one. Optional **Generate spoken version** creates a
private corrected-sentence clip. No dictionary entries, translations, vocabulary
or new pictures are generated by practice.

## Tuning logs and learner reports

Private `PictureCapture` JSON retains the following for up to 30 days:

- input modality, languages, optional proficiency, model and prompt/recipe versions;
- raw ASR transcript, normalised representation, learner-confirmed words and feedback;
- recognition questions, suspect surfaces, server decisions and suppressed written-form edits;
- bounded review output (including validation failures), actual stage timestamps,
  elapsed durations, returned usage/charges and parent attempt references;
- optional learner labels, notes and “what I actually said” corrections.

Server operational logs contain attempt IDs, stages and error types, not learner
words, audio, images, API credentials or provider output. JSON exports exclude
media bytes, private storage paths and credentials. Returned usage is evidence of
usage, not proof that the feedback is correct. Recognition uncertainty is a model
judgment, not an acoustic confidence measurement.

**Practice history and logs → Download my practice log** exports only the signed-in
learner's attempts. **Words and practice log** on an attempt allows a problem
report, intended wording, and sharing/revocation. A sharing-only submission does
not invent a success/error label. Reporting makes no AI calls.

**Share this attempt’s diagnostic log with dictionary owners** is optional and off
by default. When selected it permits active owners/co-owners to inspect that
attempt's diagnostic text, including transcripts and feedback, through **View
shared practice logs**. It grants no access to unshared attempts or private
recordings. The sharing choice can be revoked on the attempt. No new role or broad
administrative visibility is granted.

The authenticated endpoint is `practise/describe/log/`: default download of one's
own logs; `?shared=1&view=1&limit=20` is an inline view for owners/co-owners of
explicitly shared logs. `limit` is bounded to 1–200. Source withdrawal, dictionary
archival, expired/cleared attempts and learner participation withdrawal invalidate
log access as well as practice access. Export responses are private/no-store.

## Safety of retries and deployment

Each provider stage commits a claim before network I/O; receipts and separate
accounting keys prevent duplicate paid requests on repeated taps or redelivery.
Failed/discarded attempts still count toward the existing account/dictionary
allowance. Failed or uncertain network requests never repeat automatically.
Clearing an attempt removes its private logs and media through existing cleanup.

No migration, application dependency or deployment-permission change is needed.
Existing first-version feedback remains private history; new attempts use the new
review recipe. A session must authorise the new recipe before paid work proceeds.

Regression coverage includes Swedish notation and suspect-word cases, preserved
grammar errors, typed spelling, mode/level provider payloads, session scope and
expiry, uncertainty confirmation accounting, real rendered-button submission,
asynchronous draft recovery, optional audio, private/shared log access and
revocation/withdrawal, validation failures and learner reports. Provider requests
are mocked. Real speech and pedagogical quality are tested on the laptop before
AWS; shared production logs can then support a larger tuning sample.

## Cost presentation

The priced speech button is an **additional** generation estimate, not an all-in
practice price. It assumes 30 seconds of output plus a small text-input allowance.
After generation, the player replays the saved clip without another AI request.

The quiet cost-so-far line combines existing recognition and AI-review usage with
any private speech-generation reports. Recognition and feedback use returned
token usage and configured prices; speech generation uses the existing duration
estimate. Details sit inside **Words and practice log → Cost details** and are
also included in diagnostic exports. No billing algorithm or tariff changes.

Unknown usage, pending calls and uncertain audio costs are labelled explicitly;
a partial sum is never labelled a complete total. Edited attempts do not count
recognition or reviews already incurred in the earlier attempt a second time.
These estimates describe AI usage, not hosting or final provider invoices.

## Help with uncertain recognition

New spoken attempts can show an **I understood…** panel when the image-aware
review finds a plausible alternative to the recogniser's words. It shows a
possible interpretation and up to three suggested words/phrases, with short
meanings in the chosen explanation language. These are hypotheses about
intention, not diagnoses of pronunciation. The image is context; it is never an
answer key. Genuine grammar outside those replacements is preserved for feedback.

An uncertain recogniser spelling with a reasonably clear interpretation is shown
as an interpretation to check, without a spelling-comparison arrow or a claim
that the learner used a foreign word. The raw transcript, proposed replacements
and original model question remain in private diagnostics. The reviewer explicitly
distinguishes uncertainty about intended meaning; when that is unresolved, the
page still asks a prominent meaning question. Proposed lexical changes still need
learner confirmation before language feedback; they are never applied silently.
Italian `Carotte e lattuga.` is a regression example of this presentation policy,
not a pronunciation diagnosis or a fixed substitution rule.

When uncertain speech produces useful suggestions, the background worker now
automatically prepares private model pronunciations of every suggested word and
example phrase. Words are prepared first, then phrases; each player becomes
available as its clip finishes. The page shows progress and refreshes itself.
Nothing autoplays, and replaying saved audio is free. There are at most three word
clips and three phrase clips per attempt. Clear attempts and typed input generate
none of these help clips. Failed or uncertain audio requests are not repeated
automatically. Word/phrase audio costs are included in cost details and the private
export; the diagnostic request event marks them as automatic. These clips do not
add dictionary content.

All private practice pronunciations (words, phrases and final feedback) use the
OpenAI practice voice covered by the practice estimate and consent. The
dictionary's Google word-provider setting continues to apply to published
vocabulary, not these private clips. This avoids a provider-policy mismatch that
could stop the word clip while leaving its example phrase usable.

The initial practice estimate includes an allowance for those six possible help
clips, based on five seconds per word and ten seconds per phrase plus their text.
This is a rough allowance, not a fixed charge or a guaranteed ceiling; actual
usage varies. The new recipe requires fresh session permission before these
automatic requests. Old attempts are not silently backfilled. The optional spoken
version of final feedback still requires its separate priced button.

**Yes, use these words** confirms the displayed interpretation and starts the
existing additional review, without repeating speech recognition. **Use different
words** opens the editable original transcript; the learner can keep or change
it. **Try again** offers a new recording for the same image. No recognition panel
is added to ordinary clear attempts or typed input. If no useful hypothesis is
available, the existing clarification/edit flow remains available.

The reviewer must treat Italian `tabolo` → `tavolo` and `Ce` → `C'è` as contextual
possibilities, never fixed substitutions. Written accents/apostrophes must not
be criticised as spoken errors. The reviewer still sees no waveform and makes
no pronunciation, accent or fluency assessment. Model suggestions can be wrong.

The log distinguishes the raw transcript, proposed wording, learner-confirmed
wording, confirmation method (suggestion, edited or unchanged), requested audio,
its status, and bounded audio `stage`/`failure_code` values when available. Unknown
codes are omitted as null; raw provider error messages, keys and paths are never
exported. Existing report labels and intended-wording notes remain
available. Owners/co-owners see only attempts explicitly shared with them; sharing
a diagnostic log does not grant access to private recordings or these audio clips.

Start a new attempt after installing this recipe. The changed recipe requires
fresh practice-session permission; existing failed attempts do not restart.
No schema, dependency, tariff or deployment-permission change is needed.

## AWS speech accounting repair — 19 November 2026

Speech could finish its provider request but fail when storing the charge:
`capture:<UUID>:practice_transcription` exceeded the billing reference's
64-character database limit. PostgreSQL enforces that limit; SQLite does not.
Confirmed feedback and generated-speech references could also exceed it.

Overlong references now keep the full capture UUID and use a stable digest for
the stage suffix. Short existing references, full operation names in ledger
metadata, accounting stage keys, tariffs and retry rules are unchanged. This
requires no migration. Workflow regressions validate the field's length on
charge inserts even under SQLite, including voice, confirmation and optional
spoken feedback. The original references fail those regressions.

After installing the repair, explicitly start a new speech attempt. Existing
failed attempts remain private and do not restart provider requests automatically.


## Picture rotation and My practice

Picture selection now keeps a private history per learner and dictionary across
logins and devices, using the existing contribution-preference JSON field. It
aims for two unseen pictures then one review once a review pool exists, avoids
the five most recent pictures when the category is large enough, and reviews
less-used, older pictures first. Small categories relax the recent-five rule;
two pictures alternate and one picture necessarily repeats. Existing category,
acceptance and withdrawal checks still determine the eligible pictures. Shared
file copies count as one picture; separately uploaded files are distinct.

The first visit seeds the rotation from up to 2,000 retained private practice
attempts. Earlier pictures merely viewed or skipped cannot be reconstructed.
Pinned links, reloads and Try again keep the selected picture and do not add
consecutive exposures. Explicit entry links remain usable. The history remembers
up to 2,000 picture identities, storing hashes, exposure counts and ordering,
with no words, recordings or media paths. Workflow changes preserve this UI
metadata and never treat it as permission for paid processing. Viewing or
skipping a picture creates no practice attempt, consumes no allowance and makes
no AI call. No migration or new dependency is required.

The existing history/log section is now **My practice**. It shows pictures in the
rotation history, plus completed attempts, completed spoken attempts and active
practice days in the last 30 days. These totals are private to the learner and
use the dictionary's current language. Cleared and expired attempts are excluded;
recognition clarification and failed requests are not completed attempts. Active
days include days with an attempted request, using the site's configured time
zone. Pictures explored counts retained rotation identities, including earlier
practice; it is bounded by the 2,000-picture history. The overview measures
activity, not proficiency, pronunciation quality or learning gains. Existing
shared diagnostic-log permissions are unchanged.
