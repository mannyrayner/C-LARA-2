On 29 September Manny reported that the AWS update sequence worked. Kate and
Axel had asked how to start; Stéphanie expressed interest and expected to try

The preceding decision to defer introductory-wording changes until the optional
image-generation discussion is preserved. No image-generation, lookup, practice,

## Implementation

- Base: public `main`, `c72c33b992db50365d2489fefb0a27598210abd6`.
  Its content tree `dd40155a68b8869ba1b6373dfb747a1309a49d37` was verified against
  the local snapshot used for the patch; an isolated worktree preserved earlier work.
- Save is available at both ends of the contribution/wording form. Media Save
  buttons explicitly affirm permission through their caption and submit value;
  ordinary Django media-consent validation remains in force.
- Source inspection found a likely cause of missing warnings: local IndexedDB
  persistence reset the same dirty flag used by beforeunload. A restored draft
  also did not set it. These flags now continue to represent unconfirmed server
  saving. This is a code-supported explanation, not a recreation of Cathy's
  exact device/session.
- In-app links offer Save and leave, Keep editing, or Leave without saving.
  Failed saves remain in the form. Browser Back/reload/close use native warnings
  where available; mobile lifecycle events attempt recovery persistence.
- The original chosen photo is retained before asynchronous resizing. Draft
  writes are ordered, save freezes form input before awaiting preparation, and
  duplicate clicks retain the existing idempotent receipt behaviour.
- Active-account usernames are selectable by dictionary owners, matching the
  existing ordinary-project collaborator pattern. No emails are listed. Members
  and editors cannot obtain the account picker or invite others; dictionary
  membership still requires acceptance. Partnership menus list joined members.

## Verification

- 70 Django app tests pass with Python 3.12.14, Django 5.2.17 and OpenAI SDK 3.19.2.
  Providers are mocked. Three new tests cover required media permission,
  owner-only username listing, inactive-account exclusion, invitations and roles.
- `save_ux_browser.cjs` passes in Chromium 153.0.8010.0 using iPhone 13 and Pixel 7
  viewport profiles. It checks both Save placements, single-click media consent,
  text-only saving, persisted/restored-photo warnings, native reload warning,
  all three leave-dialog choices, delayed photo preparation, blocked IndexedDB,
  a lost successful server response followed by an idempotent retry, and account
  selection. Checked pages have no horizontal overflow or uncaught JS errors.
  Screenshots of the upper Save panel and leave dialog were visually inspected.
- The existing recording/partnership browser rehearsal passes with synthetic
  camera and microphone fixtures: denial recovery, selected-device meter,
  audible recording, silent-retake rejection preserving prior audio, draft
  restoration, request/reply, discussion, editor acceptance, saved playback,
  and wording/search while retaining media. An initial run timed out waiting for
  the synthetic microphone meter; the diagnostic rerun passed without changing
  application recorder code. This is controlled-browser evidence, not a claim
  about physical recording devices.
- The environment's old cached Chromium executable was truncated. Re-expanding
  the retained browser package restored the executable before final checks.
- No paid API calls or production actions. No new migration or dependency.

Browser checks use a disposable database and generated media. To repeat the
focused check, set the Playwright/Chromium variables documented in
`browser_rehearsal.py`, then run from the repository root:

```bash
python -c 'from pathlib import Path; from experiments.community_dictionary.browser_rehearsal import main; main(Path("experiments/community_dictionary/save_ux_browser.cjs").resolve())' /tmp/community-save-ux
```
